# Products OS — one protocol, swappable modules, many doors

The mindset: this is an operating system for agent-run brands, not a
collection of apps. Modules sit upstream or downstream of each other,
speak QP on every boundary, and any module can feed many products. Adding
a product means wiring existing modules, rarely building new ones.

## Upstream modules (factories — they produce)

- Freaktown animation studio: avatar, voice, takes, walkouts, performance
  contracts. Feeds influencer-studio, autopilot freaks, clip-farm source
  material, guest-booking talent, storefront faces. One stage, many shows.
- Funnylab lineages: weights plus frozen eval. Feeds autopilot, roast-line
  style, eval-api training pairs.
- Etsysignal roast factory: order → beats → bundle → portrait → gift URL.
  Feeds roast.pet orders, clip-farm inputs, Pog character returns.
- Trend radar: candidate flow. Feeds spawn, autopilot new blood.

## Midstream modules (the plane — they route and prove)

- Influence graph + queue + receipts: passports, reconcile, HTask rail.
- Money-proof rails: grants, spend ledger, readbacks, payouts, hiring rail.
- Eval-api judges: typed decisions for any module that needs one.
- Private studio: attested runs plus identity-free setup for any lane.

## Downstream modules (doors — they distribute and earn)

- Dash lenses (one shell, many views), party rooms, watch loop.
- Storefronts: own subdomains plus Etsy as a second door.
- YouTube / socials publish surfaces (gated) with analytics read-back.
- ChatGPT plugins / apps surface (eventual): our MCP tools plus
  product actions exposed through OpenAI's app/plugin contract as one
  more downstream door — same grants, same receipts, same queue behind
  it. External surface, never a second kernel.
- Guest bookings: outside agents enter through doors, never through walls.

## Globalized analytics (the nervous system)

Every door reports the same event shape (artifact, lineage, reaction,
source, ts) into the reward log. Per-lineage rates roll up across doors,
platforms, and regions — one laugh-rate per lineage worldwide, sliced by
door when needed. YouTube retention, room HAHA/CLAP, Etsy orders, watch
reactions: different speeds, one schema, none trusted alone. Frozen eval
plus human taste keep veto over the numbers so global optimization never
breeds global slop.

## Rules of the OS

- Modules depend downward only (doors on plane, plane on factories, all
  on the protocol). No lateral internals: bundles, events, receipts cross.
- A new product is a wiring diagram over existing modules plus at most
  one new leaf (function + gate + lens).
- A new door (Etsy today, ChatGPT plugins tomorrow) gets the same
  treatment: capability-scoped access, grants before effects, readback
  before settle, receipts in the one log.
- Data flows are organized once: reward events, inference judgments with
  distributions, money events with readbacks — three streams, typed,
  append-only, replayable.
